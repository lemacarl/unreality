# Contributing

## Workflow
- Branches: `feat/<issue#>-<slug>`, `fix/<issue#>-<slug>`, `chore/<slug>`, `docs/<slug>`, `spike/<slug>` (throwaway prototypes, never merged; ADRs land via `docs/` or `chore/` branches).
- Commits: conventional commits (`feat:`, `fix:`, `docs:`, `chore:`, `test:`).
- PRs: title `<type>: <summary> (#<issue>)`, body has `Closes #<issue>`, how it was tested, open concerns. Squash-merged after CI is green and independent review approves. Never push to `main` directly.
- Docs and CHANGELOG are updated in the same PR as the change.
- No new dependency without an ADR. Never weaken tests or lint to pass CI.
- Public repo: no personal data, screenshots of your screen, or secrets in issues, PRs or logs.

## Local development
Build commands are in the [README](README.md#build-and-run). Layout: `Sources/UnrealityCore` (pure logic), `Sources/UnrealityPlatform` (OS integrations), `Tests/`, and the app shell in `App/` described by `project.yml`.

- `Unreality.xcodeproj` is generated by XcodeGen and gitignored. Edit `project.yml`, then run `xcodegen generate`; never hand-edit or commit the project.
- Dev builds must use a stable signing identity and bundle ID, or macOS drops Screen Recording/Camera/Accessibility grants on every rebuild. The project signs ad hoc (`CODE_SIGN_IDENTITY = -`) by default so a clean checkout builds without an Apple Developer team; ad-hoc signatures change on every build, so for permission work select your own team and a development certificate in Xcode's Signing & Capabilities for the `Unreality` target (local change only; do not commit team IDs). Keep the bundle ID `com.lemacarl.unreality`.
- Secrets live in the Keychain only.

## Agents and models
| Role | Model | Effort | Used for |
|---|---|---|---|
| PM | Claude Sonnet 5.5 | Medium | Planning, issues, docs, merge decisions |
| Builder | Claude Opus 5.5 | Medium | Implementation, spike prototypes |
| Reviewer | Claude Opus 5.5 | High | Code, functional, privacy/security reviews (fresh context, never the PR's builder) |
| Researcher | Claude Sonnet 5.5 | Medium | Research for ADRs; gathers evidence, does not decide |

Builder, Reviewer and Researcher are defined in `.claude/agents/`; the PM is the main orchestrating session.

# Contributing

## Workflow
- Branches: `feat/<issue#>-<slug>`, `fix/<issue#>-<slug>`, `chore/<slug>`, `docs/<slug>`, `spike/<slug>` (throwaway prototypes, never merged; ADRs land via `docs/` or `chore/` branches).
- Commits: conventional commits (`feat:`, `fix:`, `docs:`, `chore:`, `test:`).
- PRs: title `<type>: <summary> (#<issue>)`, body has `Closes #<issue>`, how it was tested, open concerns. Squash-merged after CI is green and independent review approves. Never push to `main` directly.
- Docs and CHANGELOG are updated in the same PR as the change.
- No new dependency without an ADR. Never weaken tests or lint to pass CI.
- Public repo: no personal data, screenshots of your screen, or secrets in issues, PRs or logs.

## Local development
Build commands are in the [README](README.md#build-and-run). Layout: `Sources/UnrealityCore` (pure logic), `Sources/UnrealityPlatform` (OS integrations), `Tests/`, and the app shell in `App/` described by `project.yml`.

- `Unreality.xcodeproj` is generated by XcodeGen and gitignored. Edit `project.yml`, then run `xcodegen generate`; never hand-edit or commit the project.
- Dev builds must use a stable signing identity and bundle ID, or macOS drops Screen Recording/Camera/Accessibility grants on every rebuild. Signing comes from `Config/Signing.xcconfig`, which signs ad hoc (`CODE_SIGN_IDENTITY = -`) so a clean checkout builds without an Apple Developer team. Ad-hoc signatures change on every build, so for permission work copy `Config/Local.xcconfig.example` to `Config/Local.xcconfig` (gitignored, pulled in by `#include?`), set your `DEVELOPMENT_TEAM` and `CODE_SIGN_IDENTITY = Apple Development`, and run `xcodegen generate`. Do not change signing in Xcode's Signing & Capabilities: that edit lives in the generated project and is lost on the next `xcodegen generate`. Never commit team IDs. Keep the bundle ID `com.lemacarl.unreality`.
- Hardened runtime is enabled, but ad-hoc Debug builds are signed without it, so a missing hardened-runtime entitlement (for example `com.apple.security.device.camera` for camera access) only shows up in Release builds or builds signed with a real identity. Test permission work in one of those.
- Secrets live in the Keychain only.

## Lint rules
`core_no_os_imports` (in `.swiftlint.yml`) is an allow-list: files in `Sources/UnrealityCore` and `Tests/UnrealityCoreTests` may import only Foundation, Dispatch, Observation, Synchronization and RegexBuilder (tests may also import UnrealityCore and Testing). It ignores comments and strings and catches attributed and scoped imports (`@preconcurrency import X`, `@_exported import X`, `import struct X.Y`). New core dependencies (GRDB, via the storage issue #16) must be added to the list in the same PR as their ADR. To check the rule after editing it, add throwaway probe files such as `Sources/UnrealityCore/ZZProbe.swift` containing `@preconcurrency import AVFoundation` and `import struct Foundation.Data`, run `swiftlint --strict`, confirm only the first is flagged by `core_no_os_imports`, then delete the probes.
